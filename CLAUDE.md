# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project overview

地铁键速 · Metro Typing · Guangzhou (named 一键到底 before v0.1.6, 拼音快线 · Pinyin Express before v0.1.0) — a browser typing game. Players pick any Guangzhou Metro line (all 19 lines of the 2026 network since v0.3.2, incl. Guangfo + APM), type each station name in toneless pinyin to drive the train forward, and are scored on speed, accuracy, and combos. Difficulty levels derive from station-name length. A 5-stage pixel makeover: since v0.6.0 the ride is a **pixel-art canvas city** from tiled OpenStreetMap data (`js/px/` + `js/map/`), the SVG ride map staying as the **Classic** view (a Settings choice and the automatic fallback); since v0.7.0 the level select below the hero is a full-screen **world map** (the living canvas map `OVM`, a dock, a level card) with pixel chips and dialogs (a CSS **pixel UI kit**), the SVG overview map as its fallback. Still MD3 until Stages 3–4: the hero + `#startBtn` + boot intro, `#result`/`#newBadges`, the boss stage; Stage 5 removes Classic, MD3 and the rounded webfonts.

- **Vanilla HTML/CSS/JS, no build step, no dependencies, no package manager.** Keep it that way — do not introduce tooling or frameworks unless explicitly asked.
- Run it by opening `index.html` in a browser or via any static server (VS Code Live Server is the recommended workflow). Must keep working from `file://` — so **plain `<script>` tags only, never ES modules**.
- Repo: https://github.com/JamieStudio-lab/guangzhou-metro-typing · Live: https://jamiestudio-lab.github.io/guangzhou-metro-typing/

## Versioning workflow (required for every user-visible iteration)

Versions are semver, currently 0.x (v1.0.0 is reserved for a milestone the user declares). For each iteration that changes what users see or play:

1. Bump `APP_VERSION` in `js/game.js` (patch = fixes/tweaks, minor = new features, major = reworks). It is displayed in the About dialog (`#aboutVer`) automatically.
2. Add a dated entry to `CHANGELOG.md` (Keep a Changelog format) and update the compare links at the bottom.
3. Commit, then `git tag -a vX.Y.Z -m "vX.Y.Z — <one-line summary>"` and `git push --follow-tags`.
4. Create a GitHub Release for the tag with the changelog entry as the notes (`gh release create` if logged in, otherwise ask the user).

## Conventions

- UI text is single-language, switched in Settings (since v0.0.6). All strings live in the `T` dict in `js/game.js` (`t(key, …args)`; values may be template functions), **always zh and en**; static markup is tagged `data-i18n="key"` (on an icon button's inner `<span>`) and refreshed by `setLang()`, dynamic strings call `t()` at render time. Default follows `navigator.language`. Station names/pinyin stay 汉字 + pinyin in both languages; per-line `desc:{zh,en}` in `js/data.js` (from the zh/en Wikipedia articles) via `descOf()`.
- Difficulty tags come from `diffOf(key.length)`: ≤7 short, ≤12 medium, else long; a line's card level 1–4 = `L.lvl`, the quartile of `L.diff` (avgLen + stations × 0.09; boss 4). Speed heat colors from `heatOf(perf)`: green/amber/red.
- Scores/bests/stars are **session-only when signed out** (About's footnote promises this — don't add local score persistence; stars = `bests[key].stars` ∪ `cloudStars()`); signed-in players' finished runs upload via `js/cloud.js`. localStorage keys: `lang`, `theme`, `sb_session`, and the pixel settings `ride` (pixel|classic), `pxScale` (2|3; the menu 3× only ≥ 600 CSS px wide), `weather` (auto|clear|rain), local only, never cloud-synced — via the `store` helper in `js/game.js`, which no-ops when storage is unavailable.
- Playable data covers all 19 lines of the 2026 network as they run today (Line 12 = opened east section, Line 21 starts at 天河公园, no Line 3 airport branch / Knowledge City line); distances approximate; fan-made, not affiliated with Guangzhou Metro. A playable line's stations must exist in `js/geo.js` by 汉字 and need pinyin, `segKm` and `labelPos` in `data.js`; a `loop:true` line closes its map path decoratively but plays linear. New `mode` ids must also go into the `scores.mode` CHECK in `supabase/setup.sql` (+ a migration on the live DB).
- Line colors are the official palette (`L.color` in `data.js`, matches `geo.js`); everything runtime (cards, tabs, map strokes, confetti, `--lc`, PAL's `lsh.<id>`) derives from it. `--l1/--l2/--l3` (+`--l4..6`) are MD3 decoration only — keep the three in sync with L1/L2/L3.
- Pinyin is displayed toned but matched tonelessly (市二宫 → `shiergong`).
- Respect the existing style: compact code, minimal comments, `prefers-reduced-motion` support, `--lc` accent recolors per line.
- **Classic fallback.** A run rides Classic when Settings says so (it affects the ride only), there is no 2D canvas, a pixel script fails 3 times, `RIDE.prepare` rejects or takes > 12 s, any `RIDE` call throws (rest of the session), or the governor gave up (`RIDE.giveUp`: from the next ride, one `pxSlow` toast); Settings then shows the `pxOff` note and picking Pixel retries. Boss mode never starts `RIDE`. Every game.js use of a pixel global is `typeof`-guarded or runs after `pxLoad()`.
- **Loading (since v0.7.0).** First paint loads no pixel script (the kit CSS, ~12 KB gz with the world screen, styles it with static `--px-*` hexes and `[data-lc]` fallbacks; the hero covers the first screen). `PX_MENU` (≤ 280 KB gz) loads after `load` + idle, or at once on a `#startBtn` / chip click or when `#pick` shows (`saveData`: only those), and mounts `OVM` behind the hero; `ovlife.js` (12 KB gz) follows. The rest of `PX_JS` loads on idle ~3 s after boot (never under `saveData`); `fonts-han.js` only where a nickname shows. The SVG `#ovMap` (built at boot) shows until `OVM`'s first frame and is the session's fallback (`ovFail`; then only `PX_FONT` loads) on no 2D canvas, the menu set failing 3×, an `OVM` throw (`ovTry`) or no frame within 8 s, with its rotation and `#ncue` (the pixel map is north-up).

## Pixel UI kit (since v0.7.0)

The DOM twin of the canvas pixel look, for the world screen, chips and dialogs; reference `mockups/pixel-menu/SPEC.md` §3–4 (kit) and `mockups/pixel-world/SPEC.md` §2–4 (the world screen's sizes, behaviour contract, markup, strings), rules also atop the kit section of `css/style.css`.

- **Scale.** `s` = Settings pixel size, 3× only when `innerWidth ≥ 600`; K = max(1, round(s × dpr)); `--pxk` = K / dpr on `<html>` (`pxK()` at first paint, `pxChrome()` on resize / dpr / Settings); `--pxu` = 1 art px. Every size, border, offset and line-height is a whole `--pxu` multiple (fluid ones via `round(down, …, var(--pxu))`). `html.nar` = a phone (≤ 560 CSS px: icon-only chips, 2-row plate, swiping dock, the card a sheet). `OVM` mounts with the same `s`.
- **Tokens** `--px-*`: static hexes for both themes, equal to their PAL role (night / day); `PXC` in game.js repaints them from PAL, `check-kit.js` asserts both:

  | Tokens | PAL role |
  |---|---|
  | `page` `ground` · `fill` `fill2` `off` | `bg` `land.d1` · `ui.panel`/`ui.panel2`, swapped, `ui.panel2`/`ui.panel` |
  | `edge` `hi` `lo` `shadow` `ink` · `text` `dim` `outline` | `ui.edge` `ui.hi` `ui.lo` `shadow` `ink` · `text` `ui.dim` `textOutline` |
  | `accent` `accent-lo` `accent-hi` · `accent-tx` `accent-sign` `bad-sign` | `ui.accent` `ui.accentLo` `fire.core`/`fire.t2` · `ui.accentTx` `ui.accentSign` `ui.badSign` |
  | `onaccent` `onbad` · `good` `warn` `bad` · `fire-*` | better of `text`/`textOutline` on the sign · `hud.*` · `fire.*` |
  | `paper` `paper-lo` · `screen` `led` `led-off` `led-glow` | `stn.fill` `stn.lo` · `led.bg` `led.on` `led.off` `led.glow` |
  | `tag-good` `tag-mid` `tag-hard` `tag-bad` | the hue's first step ≥ 4.5:1 on `fill` and `fill2` |
  | `--lc` `--lc-ink` `--lc-hi` `--lc-lo` | `[data-lc=<id>]` → `lsh.<id>.sign/ink/hi/lo` (`pxLc()`; `boss` = bad-sign/onbad/fire-t2/tag-bad) |

  Text colours only: `text`, `dim`, `accent-tx`, `tag-*`, `onaccent` on `accent-sign`, `onbad` on `bad-sign`, `--lc-ink` on `--lc` (all ≥ 4.5:1).
- **Components** (classes, sizes in art px): `.pk-btn` 21 (`.pri` `.danger` `.pk-ico`) · `.pk-chip` 19 (`.on` `.danger`) · `.pk-tab` 19 (`[aria-selected=true]` = `--lc` fill, pressed) · `.pk-fab` · `.pk-panel` / `.pk-inset` (`.dots`) · `.pk-field` (+ `aria-invalid`, `.pk-msg`) · `.pk-switch` (`role=switch`) · `.pk-cycle` · `.pk-row` 18 (`.me`; `.grow` `.dim` `.acc`) · `.pk-badge` 19 (`.off`) · `.pk-dlg` (native `<dialog>`, `::backdrop` = checker dither, placed by `pxDlg()`; Esc closes all, backdrop click all but Account) · `.pk-pill` 19 (`.on` `.dim` `.x`) · `.pk-roundel` 13 (`.sm` `.w`) · `.pk-tag` 13 (`.good .mid .hard .bad`) · `.pk-toast`. `.is-hover .is-focus .is-active .is-off` mirror the states.
- **States.** hover = `fill2` · focus-visible = 1 art px `accent` outline · active = shift (1, 1), bevel inverted, no drop shadow · disabled / `aria-disabled` = `off` fill, `dim` text · reduced motion: no shift.
- **Type.** `.f8 .f10 .f12 .f16` = FP8…FP16 at N × `--pxu` (line-heights 10/12/16/20), no synthesis, smoothing, kerning or letter-spacing. Components trim to the cap box (`text-box: trim-both cap alphabetic`) at odd heights (21/19/13). Nicknames are always FP12 (the face `fonts-han.js` extends).
- **Icons.** 9×9 `<svg class="pki" aria-hidden="true"><use href="#pki-NAME"/></svg>` from the inline sprite (`currentColor` + `--pki-*` tones): gear close user home down up left right plus minus reset top stn inter; badges ticket star crown train maglev flame target line; roundels `#pk-rd`/`#pk-rdw`; the world's `#pw-*`: trophy info play, stars s7 s15 (+`e` ghosts), cursor corner cor, medallions rd rdw. New ones: draw in `mockups/pixel-menu/icons.js` (or `pixel-world/world.js`), paste the `<symbol>`.
- **Never**: `border-radius`, blur, `backdrop-filter`, `filter`, opacity fades, alpha colours, soft shadows, transitions, gradients other than the hard-stop 1 art px checker (the dither). Dims are dithers or darker steps.
- **World screen** (`.pw-*`, SPEC §2): no page scroll; motion = `steps()` keyframes on whole art px or `visibility`, none under reduced motion; banner / hint placed by `wLayout()`; the card's fact clamped to 2 lines in the pixel font (`wClamp`).
- **Scope.** Shared MD3 classes stay on Stage 3/4 screens: `.go` styles only `#startBtn`/`#result .go`, `.bdgchip` only `#newBadges`.

## Pixel ride rules (since v0.6.0)

From the mockup's `SPEC.md`, summarised in the `js/px/pixel.js` header (they bind `OVM` too):

- **One art canvas** at an integer `K` device px per art px (`image-rendering:pixelated`; no second pixel size, no CSS-scaled art). DOM over it (`#fchips`, toast, `#pxVeil`, `#goFx`) wears the kit.
- **Integer coordinates**; no sprite rotation/scaling at draw time, no `imageSmoothing`; vector shapes go through `PX.mask()`.
- **Palette only**: every pixel is a `PAL` colour of the active theme, by role key, never hexes; `RIDE.audit()` and `OVM.audit()` must report **0** after any drawing change (both themes, mid-zoom and mid-dissolve too).
- **Pixel fonts at native sizes only** (`FP8`–`FP16`; `FP10`+ for toned pinyin). Fades are **Bayer dithers**, never alpha; light from the top-left; 1 px outlines in the ramp's darkest step.
- The OSM attribution stays on the canvas. Reduced motion = cuts, clear weather, no traffic, no shake.
